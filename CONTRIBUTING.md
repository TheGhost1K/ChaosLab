# Contributing to ChaosLab

Мы рады любой помощи: новые системы, методы анализа, оптимизации, исправления
багов, улучшения UI.

## Быстрый старт для разработчиков

```bash
git clone https://github.com/TheGhost1K/ChaosLab.git
cd ChaosLab
dotnet build ChaosLab.slnx
dotnet test
```

Подробности — в [docs/articles/development.md](docs/articles/development.md).

## Что мы приветствуем

### Новые системы

Классические или современные хаотические модели. Обязательно:

- Ссылка на статью/книгу-источник
- Параметры по умолчанию дают хаос (λ₁ > 0)
- Аналитический `JacobianVectorProduct` (если возможно)
- Тест на известное значение λ₁

### Новые методы анализа

Фрактальные, энтропийные, топологические, информационные методы.
Требуется:

- Ссылка на оригинальную статью
- Проверка на известной системе
- Отображение результата в UI (текст или график)

### Оптимизации

Профилирование показывает, где время. Мы принимаем:

- Параллелизм через `Parallel.For`/`ForEach`
- SIMD через `System.Numerics`
- Кэш-дружественные перестановки циклов
- Устранение аллокаций в hot path

Не принимаем:

- `unsafe`, `stackalloc`
- Микрооптимизации без бенчмарков
- Изменения точности ради скорости

### UI/UX

- Тёмная тема, высокий контраст
- Без тяжёлых анимаций
- Все контролы привязаны к VM (без code-behind)
- Поддержка DPI (проверяйте на 125%, 150%)

## Процесс

1. Откройте issue с описанием проблемы/фичи
2. Дождитесь обсуждения (не начинайте кодить сразу)
3. Форк → ветка `feature/xxx` → PR
4. Code review → merge

## Стиль кода

- См. `.editorconfig`
- Коммиты в стиле [Conventional Commits](https://www.conventionalcommits.org/)
- Один PR = одна фича
- Не бойтесь рефакторить, но отдельным PR
